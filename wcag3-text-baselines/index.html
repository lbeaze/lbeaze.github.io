  • Japanese vs. Chinese: side lines go to the right of vertical Japanese text and the left of vertical Chinese text; emphasis dots go above horizontal Japanese and below horizontal Chinese.

Contrast

Every contrast cell in the matrix is “No data”. What the sources do say:

  • No ingested language-enablement source (lreq documents, gap analyses, orthography notes) defines a contrast value or contrast rule for any script or language.
    • Language matrix (W3C i18n)
  • WCAG 2.2 ‘large scale text’ includes ‘font size that would yield equivalent size for Chinese, Japanese and Korean (CJK) fonts’ but does not state that size.
    • WCAG 2.2 definition: large scale (text)
  • WCAG 2.2 notes that fonts with extraordinarily thin strokes or unusual features are harder to read at lower contrast. Several sources describe script-specific stroke weight (e.g. Hebrew bold ‘often quite light’; Japanese body Mincho is light; Ethiopic classic typeface is heavy and Latin is thickened to match). These are related to contrast perception but none states a contrast requirement.
    • WCAG 2.2 definition: large scale (text)
    • Hebrew orthography notes §fontstyle
    • Requirements for Japanese Text Layout (JLReq) §font_selection_and_font_size_of_heading
    • Ethiopic Layout Requirements (ELReq) §relative_typeface_weights

WCAG 2 values for comparison

Kept separate from the matrix: these are user-adjustment targets, not community defaults.

  • SC 1.4.12 Text Spacing (AA): line height ≥ 1.5× font size, paragraph spacing ≥ 2×, letter spacing ≥ 0.12×, word spacing ≥ 0.16×. Exception: languages/scripts that do not use a property conform using only the properties that exist for them.
    • WCAG 2.2 SC 1.4.12 Text Spacing
  • Understanding 1.4.12: Japanese does not use spacing following paragraphs; word spacing has no effect in languages without spaces between words. About 480 languages/scripts were tested with no adverse effects.
    • Understanding SC 1.4.12 Text Spacing
  • SC 1.4.8 Visual Presentation (AAA): width ≤ 80 characters or glyphs (40 if CJK); not justified; line spacing ≥ 1.5 within paragraphs; paragraph spacing ≥ 1.5× line spacing. Presentation aspects not used in a writing system need not be applied.
    • WCAG 2.2 SC 1.4.8 Visual Presentation
    • Understanding SC 1.4.8 Visual Presentation
  • These WCAG 2 values are user-adjustment targets or mechanisms, not authoring defaults. They are listed for comparison and are not used in the matrix cells.

Text decoration
● Convention Underline further from baseline than Latin; avoid short ink-skip fragments
  • Underlines and overlines sit further from the baseline than in Latin text, typically clearing long descenders and their diacritics.
  • If lines skip ink, very short line remnants must be avoided because they can look like dots or diacritics.
  • The Qur’an tends to use overlines rather than underlines.
  • Text borders must not expose the joins between letters; styling one letter must not break its joining.

✕ Not used No letter spacing (cursive); stretching via kashida instead
  • Spaces are not added between characters except micro-spacing at non-joining letters during justification.
  • Stretching for headings, signs, or emphasis is done by elongating the baseline, unevenly, and does not correspond to Latin letter-spacing.
  • CSS Text 3 classes Arabic as a cursive script that does not admit gaps between letters; authors should avoid letter-spacing on cursive scripts.

Method and definitions

  1. Language list and script grouping extracted from the language matrix data file in the w3c/typography repository.
  2. Sources ingested: the W3C layout-requirements documents (JLReq, CLReq, KLReq, ALReq, ELReq and style guide, MLReq, HLReq, ILReq, Indic and South-East Asian drafts), the gap-analysis checklists, R. Ishida’s orthography notes for each matrix language that has a page, CSS Text 3, and WCAG 2.2 with its Understanding documents.
  3. Sections matching each characteristic were extracted and read; each cell paraphrases what a source states and links to the section.
  4. “Letter aspect ratio” is mapped to the height of a script’s basic letters relative to Latin x-height and cap-height (as the orthography notes compare them), or to the letter face within the square character frame for Han/Kana.
  5. “Padding” is mapped to margins and text-area definitions, and to page-direction statements that reverse start/end padding.
  6. Whether a script has case is taken from the Unicode Character Database when no prose source covers it.
  7. Hangul and Kore matrix rows are combined; Han’s Simplified and Traditional rows are combined, with differences listed as exceptions.
